# Проект

Домашнее задание по курсу "Llm-инженер".

Omni-ассистент который по голосовому вводу проводит исследование в интернете
и выдает ответ в виде голосовых дорожек, от лица персонажа с загруженной картинки. 

# Как запускать

## Из консоли

```
# Надиктовать вопрос (запись до Enter)
uv run start-bot --record --speak

# Вопрос из аудио файла
uv run start-bot --audio recordings/2026-08-27T19-03-11.wav --speak

# Вопрос текстом
uv run start-bot "Когда вышел Django 6.0?" --speak

# Персонаж картинкой
uv run start-bot "экскурсия по горе Машук для детей 7-8 лет" --image docs/persona_images/hulk/images.jpeg --speak

# Персонаж текстом
uv run start-bot "экскурсия по горе Машук для детей 7-8 лет" --narrator "угрюмый злой халк" --speak
```

Ответы упадут в папку spoken: вопрос, облик персонажа и итоговый текст - всегда,
звуковые дорожки - при `--speak`.

Каталог задаётся переменной `SPOKEN_DIR` (по умолчанию папка `spoken`).

## Из веба
Запуск:
```
uv run omni-web
```

Открыть приложение, загрузить картинку персонажа, надиктовать запрос и нажать "Собрать ответ".

Агент изучит картинку, проведет исследование, составит текст ответа под формат рассказчика и сгенерирует несколько звуковых файлов, которые можно прослушать. Проигрывателей в запасе двенадцать, куски сверх этого не показываются.

Если хочется сменить персонажа, но не менять вопрос и не проводить web-исследование повторно - можно поставить галочку "Взять факты последнего прогона; вопрос берётся оттуда же" (под спойлером "Настройки прогона")

Важно. Если будет стоять галочка "Взять факты последнего прогона..." - новый голосовой или текстовый ввод будет проигнорирован, т.к. собранные факты берутся из кеша.

# Как реализовано

Мультимодальная модель `qwen3-vl:4b` и модель агента `qwen3.6:35b-a3b` запускались в LmStudio и Ollama - другие провайдеры не проверялись.

В ноутбуке используется `qwen3.5:4b`, запускается на Ollama.

`qwen3.5:4b` дает результаты похуже - текста получаются более короткими, получше и интереснее будут у `qwen3.5:9b` или `qwen3.6-35b-a3b`

## Пайплайн

- Голос в консоли записывается библиотекой `sounddevice`
- Распознается библиотекой `faster-whisper`
- Картинка рассказчика отдается на описание модели `qwen3-vl:4b` (задается в env переменными `VISION_PROVIDER` и `VISION_MODEL`)
- `OLLAMA_MODEL=qwen3.6:35b-a3b` (либо `LOCAL_MODEL=qwen3.6:35b-a3b`) по описанию создает профиль рассказчика
- Граф из агентов производит исследнование в интернете через инструменты веб-поиска и создает выжимку фактов для ответа
- По этой выжимке и описанию рассказчика генерируется итоговый текст - параграфами
- Локальная llm выбирает по описанию рассказчика голос и звуковые эффекты для итоговой звуковой дородки.
- Локальная llm с промптом звукорежиссера размечает куски текста паузами
- Размеченные куски текста отдаются библиотеке `Silero` для озвучки: модель `v5_5_ru`,
  48 кГц. Голос, темп и высота уходят в неё разметкой ssml, паузы - тегами внутри
  разметки. Кусок длиннее `SPEAKING_MAX_SYMBOLS` режется по предложениям: у silero
  предел на один вызов синтеза. Выбранный эффект накладывается поверх готового звука
  средствами torchaudio

```
src/assistant/
    main.py           запуск из консоли: разбор аргументов и печать хода прогона

    graph_runs/       прогон графа: запуск, снимки, продолжение с узла
    persona/          рассказчик: облик по фотографии, профиль, голос, разметка
    integrations/     внешние библиотеки и сервисы
        listening/    запись с микрофона и распознавание речи
        speaking/     синтез silero, ssml, звуковые эффекты

        web/          поиск и вытаскивание текста страниц
    observability/    журнал прогона: консоль и markdown
    webui/            веб-интерфейс на gradio
notebooks/            ноутбук с веб-интерфейсом
scripts/              проверки отдельных этапов вручную
tests/                тесты
```

### Голос на входе

```
# вопрос из файла: формат любой, wav, m4a, aiff
uv run start-bot --audio recordings/2026-08-27T19-03-11.wav

# запись с микрофона до нажатия Enter
uv run start-bot --record

# запись фиксированной длительности
uv run start-bot --record 15
```

Запись сохраняется в `recordings/` именем по дате, путь печатается: тот же
вопрос дальше гоняется через `--audio` без микрофона.

Первый запуск качает модель распознавания в `~/.cache/huggingface`: `medium` -
около 1.5 ГБ. Дальше распознавание короткого вопроса занимает секунды, а повтор
по тому же файлу берётся из кеша расшифровок.

#### Микрофон не слышно

Строка `[запись] ... громкость 0.00` и сообщение про тишину означают, что
терминалу не выдано разрешение на микрофон.

Системные настройки → Конфиденциальность и безопасность → Микрофон, включить то
приложение, из которого идёт запуск: Терминал, iTerm или Visual Studio Code.
Разрешение спрашивается у процесса-родителя, а не у python.

Если приложения в списке нет, диалог был отклонён раньше. Вернуть запрос:

```
tccutil reset Microphone com.microsoft.VSCode
```

Вместо `com.microsoft.VSCode` подставить свой: `com.apple.Terminal`,
`com.googlecode.iterm2`. После сброса приложение нужно перезапустить.

Проверить, какие устройства ввода видны:

```
uv run python -c "import sounddevice; print(sounddevice.query_devices())"
```

#### Другие системы

Библиотеки распознавания ставятся готовыми колёсами на macOS, Linux и Windows.
Платформенная зависимость одна - запись с микрофона.

На linux колесо `sounddevice` идёт без portaudio и ищет системную библиотеку:

```
sudo apt install libportaudio2
```

Без неё `--record` вернёт «библиотека записи недоступна», а `--audio` и весь
остальной прогон работают как обычно.

На linux с видеокартой nvidia `SPEECH_DEVICE=auto` выберет cuda, и `ctranslate2`
потребует cuDNN 9 и cuBLAS. Нет их - модель не загрузится с внятной причиной,
лечится `SPEECH_DEVICE=cpu` или пакетом `nvidia-cudnn-cu12`. Там же осмысленнее
`SPEECH_COMPUTE_TYPE=float16`: `int8` выбран под процессор.

На windows ставится как есть, ничего доустанавливать не нужно.

### Рассказчик

```
# рассказчик фразой
uv run start-bot "экскурсия на гору Машук для детей 7-8 лет" --narrator "угрюмый злой халк"

# рассказчик с фотографии, сборка полями схемы
uv run start-bot "экскурсия на гору Машук для детей 7-8 лет" --image docs/persona_images/hulk/images.jpeg --persona-mode structured

# то же, но описание одной фразой
uv run start-bot "экскурсия на гору Машук для детей 7-8 лет" --image docs/persona_images/hulk/images.jpeg --persona-mode free
```

### Голос на выходе

```
# озвучка с разметкой пауз и ударений
uv run start-bot "экскурсия на гору Машук для детей 7-8 лет" --image docs/persona_images/hulk/images.jpeg --speak

# то же, но без разметки: озвучка идёт чистым текстом
uv run start-bot "экскурсия на гору Машук для детей 7-8 лет" --image docs/persona_images/hulk/images.jpeg --speak --no-markup

# без фотографии: первый голос модели, нейтральные темп и высота
uv run start-bot "Когда вышел Django 6.0?" --speak
```

Озвучка идёт кусками - вступление, каждый раздел, завершение. Путь к файлу
печатается сразу, как кусок готов: первый можно слушать, пока считаются
остальные. Файлы падают в `spoken/` именем по дате и номеру куска.

Первый запуск качает модель синтеза в `.cache/silero`: код silero и файл весов,
для `v5_5_ru` около 145 МБ. Дальше синтез идёт быстрее реального времени, а
время съедает разметка: она стоит вызова модели на каждый кусок.

### Прогон с чекпоинта

```
# какие прогоны можно переиграть
uv run start-bot --list-runs

# переиграть изложение по собранным фактам
uv run start-bot --resume 20260829-160711 --from compose

# то же, но другим рассказчиком
uv run start-bot --resume 20260829-160711 --from compose --narrator "добрый краевед"

# пересобрать факты и изложение
uv run start-bot --resume 20260829-160711 --from collect

# переиграть изложение и озвучить
uv run start-bot --resume 20260829-160711 --from compose --speak
```

Продолжение идёт теми же этапами, что обычный прогон: `--speak` и `--markup`
работают так же. Вопрос и рассказчик берутся из снимка, `--narrator` заменяет
записанного рассказчика. Персонажа полями в снимке нет, поэтому голос и разметка
строятся по блоку про рассказчика.

Снимки лежат в `.cache/checkpoints`, каталог задаётся переменной
`CHECKPOINT_DIR`. Пустое значение выключает снимки, и переиграть прогон нельзя.

### Прогон на готовых фактах

```
# изложить факты последнего прогона другим рассказчиком
uv run start-bot --reuse-facts --image docs/persona_images/hulk/images.jpeg

# то же фразой вместо фотографии
uv run start-bot --reuse-facts --narrator "добрый краевед"

# факты названного прогона
uv run start-bot --reuse-facts 20260829-160711 --narrator "добрый краевед"
```

Сбор фактов пропускается: узлы `agent` и `collect` не работают, опора берётся из
снимка и сразу идёт в изложение. Вопрос берётся оттуда же, поэтому `--reuse-facts`
не сочетается с вопросом, `--audio` и `--record`.

Рассказчик, наоборот, собирается заново: `--image` и `--persona-mode` работают
как в обычном прогоне. Без того и другого берётся записанный рассказчик. Этим
режим отличается от `--resume --from compose`, где рассказчик тоже берётся из
снимка.

### Журнал прогона

Ход прогона пишется в markdown: вопрос, облик, рассказчик, вызовы моделей и
инструментов, голос, разметка, озвучка и таблица длительностей по этапам. Путь к
файлу печатается в конце прогона.

Файлы лежат в `logs/traces` именем по идентификатору прогона, каталог задаётся
переменной `TRACE_DIR`. Пустое значение выключает журнал.

У продолжения журнал свой: имя исходного прогона плюс время рестарта -
`20260829-160711+20260829-181042`. Исходный файл остаётся нетронутым, а
происхождение видно и в имени, и в шапке.
