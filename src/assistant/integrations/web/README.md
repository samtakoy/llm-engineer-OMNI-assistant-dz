# Веб-слой

Поиск страниц в интернете, извлечение из них основного текста и кеш того и
другого на диске.

Пакет самодостаточен: он не импортирует ничего из проекта, не читает окружение
и не пишет в журнал. Перенос в другой проект - копирование папки и сборка
`WebConfig` там, где проекту удобно.

Внешние зависимости: `httpx`, `trafilatura`, `ddgs`.

## Использование

```python
from pathlib import Path

from assistant.integrations.web import WebConfig, fetch_page, search

config = WebConfig(
    user_agent = "my-bot/0.1 (+https://example.org)",
    request_timeout_seconds = 10.0,
    max_page_bytes = 2_000_000,
    cache_directory = Path(".cache/web"),
    page_cache_ttl_days = 0,
    search_cache_ttl_days = 0,
    bypass_cache = False,
)

outcome = search(query = "гора Машук", max_results = 5, config = config)
for item in outcome.results:
    page = fetch_page(url = item.url, max_characters = 4000, config = config)
```

## WebConfig

| Поле | Что задаёт |
| --- | --- |
| `user_agent` | Строка User-Agent запросов к сайтам. Часть площадок отвечает 403 на agent без контакта владельца бота. |
| `request_timeout_seconds` | Сколько ждать ответа сайта. |
| `max_page_bytes` | Сколько байт страницы скачивать, дальше поток обрывается. |
| `cache_directory` | Корневой каталог кеша. `None` выключает кеш целиком. |
| `page_cache_ttl_days` | Сколько дней годна запись о странице. Ноль и меньше - годна всегда. |
| `search_cache_ttl_days` | Сколько дней годна запись о выдаче. Ноль и меньше - годна всегда. |
| `bypass_cache` | Читать мимо кеша. Запись продолжается, поэтому прогон с обходом обновляет хранилище. |

## Кеш

Внутри `cache_directory` два подкаталога: `pages` - тексты страниц по адресу,
`searches` - выдача по нормализованному запросу. Файл на запись, имя - отпечаток
ключа, сам ключ лежит внутри вместе с версией формата и датой сохранения.

Не кешируются отказы сервисов и пустые ответы: недоступный сайт через неделю
может отвечать, ратлимит поисковика пройдёт через час, а материал по запросу
мог появиться.

В записи о странице лежит полный текст, обрезка по `max_characters` делается
после чтения: смена лимита не требует перекачки. В записи о выдаче лежат все
полученные тогда позиции, наружу отдаётся срез по `max_results`.

Кеш выдачи замораживает результаты поиска: для отладки промптов это плюс,
прогон становится воспроизводимым, а при работе над формулировками поисковых
запросов - минус, легко застрять на старой выдаче. Отсюда `bypass_cache`.
